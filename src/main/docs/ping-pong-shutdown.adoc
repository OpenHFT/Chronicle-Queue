= Ping-pong benchmark shutdown

The ping-pong benchmark waits for its reader before closing the queue and deleting
its files. Both the idle wait and the document wait observe the stop flag, and
the reader closes its own tailer on exit. The writer stops the reader in a
`finally` block, including when writing fails.

An interrupted shutdown still waits for the reader, then restores the caller's
interrupt status. This avoids closing mapped resources while the reader is using
them.

`PingPongShutdownTest` checks zero-duration and ordinary runs in separate JVMs,
including reader termination and file deletion, plus interrupted shutdown.
